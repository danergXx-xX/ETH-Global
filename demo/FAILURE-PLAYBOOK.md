# Live Demo Failure Playbook

> **Eva regula:** miec plan B na kazdy single point of failure ZANIM wejdziesz na scene. Sedziowie ceni opanowanie pod presja - panic = penalty.

> **Rio regula:** kazdy fallback testujemy raz przed demo. Jesli "fallback" sam padnie pod stresem, to nie jest fallback.

---

## Pre-demo readiness (5 min przed live)

- [ ] Localhost dev server `pnpm dev` UP (port 3000) - smoke test pelnego flow
- [ ] Pre-recorded debate clip otwarty w drugiej zakladce (YouTube unlisted, ~90s)
- [ ] Pre-connected wallet w MetaMask (Base Sepolia, mUSDC funded)

## Failure scenarios

### 1. Backend down (Railway 502 / FastAPI not responding)

**Symptom:** UI loading spinner stuck, Network tab shows 502 / timeout on `/api/debate`.

**Co Dan mowi (calm, 1 zdanie):**

> "Production backend has a hiccup - I will switch to my local instance which mirrors the same code."

**Akcja (10 sec):**
- Tab switch -> `http://localhost:3000` (already running, smoke-tested)
- Continue demo flow without restart
- Local instance hits same Anthropic API + same contracts on Base Sepolia

**Fallback URL:** `http://localhost:3000`
**Why it works:** monorepo design - frontend speaks to whichever API is on `NEXT_PUBLIC_API_URL`, locally pointed to `localhost:8000`.

---

### 2. Anthropic API rate limit (429) or model timeout

**Symptom:** Debate WebSocket opens, agents start typewriting, then stall mid-stream with `rate_limit_error`.

**Co Dan mowi:**

> "Anthropic is throttling me - this is the actual behavior our prompt cache is designed to absorb. Let me show you the exact same debate from a recording so you see the full flow without burning more tokens live."

**Akcja (5 sec):**
- Tab switch -> pre-recorded YouTube clip (unlisted, 90s, real debate from yesterday)
- Narrate over the video as if live
- After clip, jump back to UI for verdict + vote + execute (these do not need Anthropic)

**Fallback URL:** `https://youtube.com/watch?v=AITC-DEBATE-FALLBACK-001` (placeholder - to be recorded Sun morning, see FAILURE-PLAYBOOK-VIDEO-CLIPS.md)
**Why it works:** Anthropic timeouts are common at hackathon scale; pre-recorded clip preserves narrative continuity.

---

### 3. WalletConnect QR refuses to scan (WC relay flaky)

**Symptom:** RainbowKit modal opens, QR code visible, mobile wallet says "no peer found" or hangs.

**Co Dan mowi:**

> "WalletConnect relay is being moody - I have a wallet pre-connected for exactly this reason. Skipping the connect step."

**Akcja:**
- Close RainbowKit modal
- Wallet is already connected via session restore (RainbowKit persists across reload)
- Continue demo from "submit proposal" step

**Fallback URL:** none needed - pre-connected MetaMask session.
**Why it works:** wagmi `cookieStorage` persists wallet session; tested in pre-recording checklist.

---

### 4. Vercel down / preview deploy 404

**Symptom:** `demo.aitc.app` returns 404 or Vercel error page.

**Co Dan mowi:**

> "Vercel ate my deploy - here is the same UI from local, plus the GitHub repo if you want to clone it."

**Akcja (10 sec):**
- Tab switch -> `http://localhost:3000` (same as scenario 1)
- Show GitHub repo URL on slide overlay: `github.com/danergXx-xX/ETH-Global`
- Mention CHANGELOG + judges onboarding in repo

**Fallback URL:** `http://localhost:3000` + `https://github.com/danergXx-xX/ETH-Global`
**Why it works:** local dev server is the source of truth, Vercel is a mirror.

---

### 5. 0G Storage timeout on upload (testnet flaky)

**Symptom:** Verdict card shows "uploading to 0G..." stuck >15s, no CID returned.

**Co Dan mowi:**

> "0G testnet is congested - you are watching our factory pattern hand off to IPFS Pinata. Same audit trail, different rail. Production will retry 0G in the background."

**Akcja:**
- Verdict card auto-falls back to Pinata CID (factory pattern in `apps/api/storage/factory.py`)
- Show Pinata CID + open `https://ipfs.io/ipfs/<CID>` in new tab to prove it resolves
- Reference `docs/architecture.md` storage section

**Fallback URL:** `https://ipfs.io/ipfs/<auto-generated-pinata-CID>` (printed in UI verdict card)
**Why it works:** factory pattern designed pre-hackathon for exactly this; tested in 21 e2e tests.

---

### 6. MetaMask user rejects transaction (or judge wallet not funded)

**Symptom:** Vote / execute prompt -> user clicks Reject, or transaction fails with "insufficient funds".

**Co Dan mowi:**

> "Let me proceed with my judge wallet that has Base Sepolia ETH ready - this happens at hackathons all the time."

**Akcja (5 sec):**
- Click "Switch Account" in MetaMask -> select pre-funded judge wallet
- OR: invite a different judge to scan QR with their wallet (if WC working)
- Re-submit transaction

**Fallback URL:** none needed - wallet switch is in-app.
**Why it works:** judge wallet (`0x...JUDGE`) pre-loaded with 0.05 Base Sepolia ETH + voting power delegated.

## Compound failures (two things at once)

If TWO of the above hit simultaneously (rare but possible at Sun 18:00 hackathon load):

- **Skip to pre-recorded full demo:** 3-min YouTube clip showing entire flow end-to-end. URL: `https://youtube.com/watch?v=AITC-FULL-DEMO-001` (placeholder).
- Narrate over it confidently. Sedziowie wiedza, ze hackathon networks padaja.
- Mention: "This is the recording I submitted with the project, identical UI to live."

---

## Recovery posture

- **Time budget per scenario:** 10-15 sec to switch + recover, not 60+. Practice 2x before live demo.
- **Tone:** matter-of-fact, not apologetic. "X is having a moment, here is plan B" beats "oh no everything is broken".
- **Never blame:** not Anthropic, not Vercel, not 0G. "Network is congested" is enough.
- **Always pivot to value:** every failure scenario above ends with showing something the judges still see (UI, audit trail, CID, repo).
